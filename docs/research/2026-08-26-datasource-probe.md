# 免费行情数据源实测报告

**日期：** 2026-08-26
**方法：** 从**中国大陆以外**的 IP（日本，JST）用 `curl` 直接调用各接口，盘中实测。
所有结论来自实际响应，不是文档或记忆。复现脚本：[`scripts/probe-datasources.sh`](../../scripts/probe-datasources.sh)。

> 为什么要从海外 IP 测：后端计划跑在 Cloudflare Workers 上，出口是全球数据中心 IP。
> 一个「在国内能用」的接口对本项目毫无意义。

> **⚠️ 本文修订过一次。** 初版结论「港股只能拿到 15 分钟延迟」**是错的** —— 当时测的是延迟孪生接口。
> 港股有免费真实时，见第 2 节。这个错误值得留在这里作为教训：**同一台主机上的两个接口，
> 只差一个前缀，一个实时一个延迟。**

## 1. 腾讯 `qt.gtimg.cn` —— 一个源覆盖四市场

同一个接口用不同代码前缀覆盖全部四个市场，免费、无需注册、无 API key。

```
https://qt.gtimg.cn/q=sh600519     # A股 上交所
https://qt.gtimg.cn/q=sz000001     # A股 深交所
https://qt.gtimg.cn/q=r_hk00700    # 港股 —— 注意 r_ 前缀
https://qt.gtimg.cn/q=usAAPL       # 美股
https://qt.gtimg.cn/q=jp7203       # 日股
```

**返回是 GBK 编码，不是 UTF-8。** 不解码会得到乱码股票名。这是接入时最容易踩的第一个坑。

响应是 `~` 分隔的字符串，第 4 个字段是现价，第 31 个字段是时间戳：

```
v_sh600519="1~贵州茅台~600519~1308.65~1304.00~...~20260826103558~4.65~0.36~..."
                      ↑现价                        ↑时间戳
```

## 2. 港股的实时/延迟孪生接口（初版结论的错误来源）

**同一台主机上有两个接口，只差一个前缀，一个实时一个延迟。**
实测于港股上午盘、真实时间 `11:07:04`：

| 接口 | 返回时间戳 | 相对真实时间 | 判定 |
|---|---|---|---|
| 腾讯 `hk00700` | `10:52:00` | 慢 15 分钟 | 延迟孪生 |
| 腾讯 **`r_hk00700`** | **`11:07:03`** | **慢 1 秒** | **真实时** ✅ |
| 新浪 `hk00700` | `10:45` | 慢 22 分钟 | 延迟孪生 |
| 新浪 **`rt_hk00700`** | **`11:07:05`** | **同步** | **真实时** ✅ |

腾讯用 `r_`，新浪用 `rt_`。两家互相印证，可信。

**代价：** 这两个都是持牌供应商的未公开内部接口。免费拿到实时港股在法律上处于灰色地带 ——
本项目定位为**纯自用单人**、不对外分发数据，风险可接受；一旦要公开分发，这条路必须放弃。

日股试过 `r_jp7203` / `rt_jp7203`，**均返回空，没有实时孪生**。日股的实时另有解，见下节。

## 2b. 日股实时：只有 Yahoo Finance 日本站（东证下午盘实测）

在东证下午盘开盘后连打三轮，对比腾讯与 Yahoo 日本站：

| 轮次 | 东京真实时间 | 腾讯 `jp7203` | Yahoo 日本 `7203.T` |
|---|---|---|---|
| 1 | 12:35:25 | 3090 @ 11:30（上午收盘） | **3,088 @ 12:34** |
| 2 | 12:36:37 | 3090 @ 11:30 | **3,089 @ 12:36** |
| 3 | 12:37:48 | 3090 @ 11:30 | **3,086 @ 12:37** |

腾讯三轮纹丝不动（延迟 15–20 分钟，此刻仍停在午休前的上午收盘价）；
Yahoo 日本站价格在跳、时间戳跟随真实时钟、页面明确标注 `リアルタイム株価`。**是真实时。**

**代价：只能爬 HTML。** 没有公开 JSON 接口 —— 试过 `/api/v1/detail`、`/api/v1/quote/`、
`query1.finance.yahoo.co.jp` 全部 404 或不存在。数据在 Next.js 的 RSC flight 流里，
CSS 类名带构建哈希（如 `_CommonPriceBoard__price_b3h1j_64`），**对方一发版就会断**。

日股实时的三个选择：

| 方案 | 实时性 | 稳定性 | 代价 |
|---|---|---|---|
| Yahoo 日本站爬取 | ✅ 真实时 | ❌ 发版即断 | 需要能快速修复选择器 |
| 腾讯 `jp7203` | ❌ 慢 15–20 分钟 | ✅ 稳定 | 延迟 |
| 立花証券 e支店 API | ✅ 真实时 + 完整盘口 | ✅ 官方文档化 | 需开日本券商账户（免费、无月费） |

**建议的降级链：Yahoo 日本站 → 断了自动退回腾讯延迟档，并在 UI 上明确切换标记。**
这样最坏情况是变成延迟，而不是没有数据。

## 3. A股深度历史：新浪 K 线接口（EMA576 的解）

**注意主机和类名 —— 新浪有两个长得很像的 K 线接口，能力差一个数量级：**

| 接口 | 上限 |
|---|---|
| `quotes.sina.cn/cn/api/json_v2.php/**CN_MarketDataService**.getKLineData` | 1800 根封顶 |
| `money.finance.sina.com.cn/quotes_service/api/json_v2.php/**CN_MarketData**.getKLineData` | **全部历史** ✅ |

用后者：

```
https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData
  ?symbol=sh600519&scale=240&ma=no&datalen=6000
```

**必须强制 HTTP/1.1** —— 走 HTTPS + HTTP/2 会挂住不返回。`curl --http1.1` 可解。
建议带 `Referer: https://finance.sina.com.cn`。

`scale`：`240`=日线，`1680`=周线，`7200`=月线，`60`/`30`/`15`/`5`=对应分钟线。

实测深度（`sh600519`，`datalen=6000`）：

| 周期 | 根数 | 覆盖范围 |
|---|---|---|
| **日线** | **5990** | 2001-08-27 → 今（**25 年，上市至今**） |
| 周线 | 1261 | 2001-08-31 → 今 |
| **60分** | **3905** | 2022-08-16 → 今（4 年） |
| 5分 | 5025 | 2026-03-25 → 今（5 个月） |

`datalen=20000` 返回同样 5990 根 —— **这不是上限，是该股票的全部历史。**

**这彻底解决了 EMA576。** 种子残留权重 `(1-α)^k`，`α = 2/(N+1)`：

| 日线根数 | `EMA576` 种子残留 |
|---|---|
| 640（腾讯上限） | 10.8% ❌ |
| 1330（可接受下限） | 1.0% |
| **5990（新浪实测）** | **9×10⁻¹⁰** ✅ 等于零 |

**覆盖范围：仅 A股，含指数。** `sh000001`（上证指数）返回 6000 根。
`hk00700` / `rt_hk00700` / `gb_aapl` / `jp7203` **全部返回空数组**，不支持。

## 3b. 批量报价：一次请求覆盖整个自选股列表

腾讯的报价接口支持逗号分隔的批量查询，**且可以混合不同市场**：

```
https://qt.gtimg.cn/q=sh600519,sz000001,r_hk00700,usAAPL,jp7203
```

实测一次请求返回 10 只跨四市场的股票（4.4 KB，HTTP 200）：

```
sh600519  贵州茅台            1303.38   20260826115052   ← A股 实时
r_hk00700 腾讯控股            446.800   2026/08/26 11:51:10  ← 港股 实时
usAAPL    苹果                309.90    2026-08-25 16:00:01  ← 美股 收盘
jp7203    Toyota Motor Corp.  3088      2026-08-26 11:33:01  ← 日股 延迟 18 分钟
```

研究测得批量上限为 **100 只/请求**（请求 300 只只静默返回前 100）。

**产品含义：整个自选股列表一次请求即可刷新**，不必按市场拆分，也不必逐只轮询。
这同时大幅降低了触发 IP 封禁的风险。

## 4. 各市场历史数据方案

| 市场 | 冷启动深度 | 来源 | 缺口 |
|---|---|---|---|
| A股 | **5990 根日线（25 年）** ✅ | 新浪 `money.finance.sina.com.cn` | 无 |
| 港股 | 640 根日线 | 腾讯 `web.ifzq.gtimg.cn` | 距 1330 根差 690 根，需积累约 2.7 年 |
| 美股 | 待定 | Alpaca Basic（免费，需注册） | 需实测其历史深度 |
| 日股 | 约 490 根（2 年，尾部缺 12 周） | J-Quants 免费档 | 深度不足，且一年后账号自动取消 |

**共同结论：历史 K 线必须由本项目自行落库并逐日累积。** 冷启动时能拿多少拿多少，之后每天追加。
这直接决定了 Cloudflare 侧需要一个长期存放多市场多周期 OHLCV 的库，而不只是做缓存。

## 5. 三个已排除的数据源

### 东方财富 `push2his.eastmoney.com` —— 会封 IP
- HTTPS 握手完成后服务端直接断开（`curl` exit 52），IPv4/IPv6 均如此。
- 改走明文 HTTP：**第一次** `lmt=10` 返回 200，随后所有请求（包括 `lmt=5`）全部失败。
- 判定：对海外 IP 有主动封禁策略。**不能作为依赖。**

### 网易财经 `quotes.money.163.com` —— 502
经典的 A股 全历史 CSV 接口（`/service/chddata.html`）从海外返回 **HTTP 502 Bad Gateway**。

### Yahoo Finance 国际站 / Stooq
- Yahoo：`v8/finance/chart` 直接 429；cookie+crumb 流程里 `getcrumb` 返回字符串 `Too Many Request`。
  少量请求即触发。Workers 出口 IP 被众多用户共享，只会更早触发。
- Stooq：返回 200 但 body 是要求计算 SHA-256 前导 4 个零的 JS 挑战页。

## 6. 所有免费源都会封 IP —— 这是架构约束

调研过程中**新浪和东财都因为我连续快速请求而临时封禁**。新浪在约 10 次快速请求后开始返回空，
间隔 6–8 秒后恢复。东财则直接长时间拒绝。

**推论：数据接入层必须内建请求节流、结果缓存和指数退避，绝不能裸调。**
复现脚本 `scripts/probe-datasources.sh` 已按每请求 6 秒的节奏放慢。

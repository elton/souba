# 免费行情数据源实测报告

**日期：** 2026-08-26
**方法：** 从**中国大陆以外**的 IP（日本，JST）用 `curl` 直接调用各接口，盘中实测。
所有结论来自实际响应，不是文档或记忆。复现脚本：[`scripts/probe-datasources.sh`](../../scripts/probe-datasources.sh)。

> 为什么要从海外 IP 测：后端计划跑在 Cloudflare Workers 上，出口是全球数据中心 IP。
> 一个「在国内能用」的接口对本项目毫无意义。

> **⚠️ 本文修订过一次。** 初版结论「港股只能拿到 15 分钟延迟」**是错的** —— 当时测的是延迟孪生接口。
> 港股有免费真实时，见第 2 节。这个错误值得留在这里作为教训：**同一台主机上的两个接口，
> 只差一个前缀，一个实时一个延迟。**

## 1. 腾讯 `qt.gtimg.cn` —— 一个源覆盖四市场

同一个接口用不同代码前缀覆盖全部四个市场，免费、无需注册、无 API key。

```
https://qt.gtimg.cn/q=sh600519     # A股 上交所
https://qt.gtimg.cn/q=sz000001     # A股 深交所
https://qt.gtimg.cn/q=r_hk00700    # 港股 —— 注意 r_ 前缀
https://qt.gtimg.cn/q=usAAPL       # 美股
https://qt.gtimg.cn/q=jp7203       # 日股
```

**返回是 GBK 编码，不是 UTF-8。** 不解码会得到乱码股票名。这是接入时最容易踩的第一个坑。

响应是 `~` 分隔的字符串，第 4 个字段是现价，第 31 个字段是时间戳：

```
v_sh600519="1~贵州茅台~600519~1308.65~1304.00~...~20260826103558~4.65~0.36~..."
                      ↑现价                        ↑时间戳
```

## 2. 港股的实时/延迟孪生接口（初版结论的错误来源）

**同一台主机上有两个接口，只差一个前缀，一个实时一个延迟。**
实测于港股上午盘、真实时间 `11:07:04`：

| 接口 | 返回时间戳 | 相对真实时间 | 判定 |
|---|---|---|---|
| 腾讯 `hk00700` | `10:52:00` | 慢 15 分钟 | 延迟孪生 |
| 腾讯 **`r_hk00700`** | **`11:07:03`** | **慢 1 秒** | **真实时** ✅ |
| 新浪 `hk00700` | `10:45` | 慢 22 分钟 | 延迟孪生 |
| 新浪 **`rt_hk00700`** | **`11:07:05`** | **同步** | **真实时** ✅ |

腾讯用 `r_`，新浪用 `rt_`。两家互相印证，可信。

**代价：** 这两个都是持牌供应商的未公开内部接口。免费拿到实时港股在法律上处于灰色地带 ——
本项目定位为**纯自用单人**、不对外分发数据，风险可接受；一旦要公开分发，这条路必须放弃。

日股试过 `r_jp7203` / `rt_jp7203`，**均返回空，没有实时孪生**。

## 3. A股深度历史：新浪 K 线接口（EMA576 的解）

```
https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData
  ?symbol=sh600519&scale=240&ma=no&datalen=1800
```

**必须强制 HTTP/1.1** —— 走 HTTPS + HTTP/2 会挂住不返回。`curl --http1.1` 可解。

`scale`：`240`=日线，`60`/`30`/`15`/`5`=对应分钟线。

实测深度：

| `datalen` | 实际返回 | 起始日期 |
|---|---|---|
| 1500 | 1500 根 | 2020-06-19 |
| **1800** | **1800 根** | **2019-03-27（7.4 年）** |
| 2000 | **空** | 超上限 |

上限落在 1800~2000 之间。沪市、深市、创业板均验证可用。

**这解决了本项目最大的技术障碍。** `EMA576` 的种子残留权重为 `(1-α)^k`，`α = 2/(N+1)`：

| 日线根数 | `EMA576` 种子残留 |
|---|---|
| 640（腾讯上限） | **10.8%** ❌ |
| 1330 | 1.0% |
| **1800（新浪上限）** | **0.19%** ✅ |

腾讯的 640 根算出的 `EMA576` 有约 11% 来自任意种子，不可用；新浪的 1800 根把误差压到 0.2%，可用。

**但这只覆盖 A股。** 港股、美股、日股的深度历史仍需自行落库积累。

## 4. 各市场历史数据方案

| 市场 | 冷启动深度 | 来源 | 缺口 |
|---|---|---|---|
| A股 | **1800 根日线** ✅ | 新浪 `CN_MarketDataService` | 无 |
| 港股 | 640 根日线 | 腾讯 `web.ifzq.gtimg.cn` | 距 1330 根差 690 根，需积累约 2.7 年 |
| 美股 | 待定 | Alpaca Basic（免费，需注册） | 需实测其历史深度 |
| 日股 | 约 490 根（2 年，尾部缺 12 周） | J-Quants 免费档 | 深度不足，且一年后账号自动取消 |

**共同结论：历史 K 线必须由本项目自行落库并逐日累积。** 冷启动时能拿多少拿多少，之后每天追加。
这直接决定了 Cloudflare 侧需要一个长期存放多市场多周期 OHLCV 的库，而不只是做缓存。

## 5. 三个已排除的数据源

### 东方财富 `push2his.eastmoney.com` —— 会封 IP
- HTTPS 握手完成后服务端直接断开（`curl` exit 52），IPv4/IPv6 均如此。
- 改走明文 HTTP：**第一次** `lmt=10` 返回 200，随后所有请求（包括 `lmt=5`）全部失败。
- 判定：对海外 IP 有主动封禁策略。**不能作为依赖。**

### 网易财经 `quotes.money.163.com` —— 502
经典的 A股 全历史 CSV 接口（`/service/chddata.html`）从海外返回 **HTTP 502 Bad Gateway**。

### Yahoo Finance 国际站 / Stooq
- Yahoo：`v8/finance/chart` 直接 429；cookie+crumb 流程里 `getcrumb` 返回字符串 `Too Many Request`。
  少量请求即触发。Workers 出口 IP 被众多用户共享，只会更早触发。
- Stooq：返回 200 但 body 是要求计算 SHA-256 前导 4 个零的 JS 挑战页。

## 6. 所有免费源都会封 IP —— 这是架构约束

调研过程中**新浪和东财都因为我连续快速请求而临时封禁**。新浪在约 10 次快速请求后开始返回空，
间隔 6–8 秒后恢复。东财则直接长时间拒绝。

**推论：数据接入层必须内建请求节流、结果缓存和指数退避，绝不能裸调。**
复现脚本 `scripts/probe-datasources.sh` 已按每请求 6 秒的节奏放慢。
